# 模型工作流说明

## 总体逻辑

系统仍按这条线运行：

```text
天气 -> 街区 -> 班长 -> 店铺
```

- 天气：大盘环境、涨跌家数、成交额、风险环境。
- 街区：板块强弱、短期回调、转弱、退潮。
- 班长：板块龙头或核心候选。
- 店铺：具体个股评分、位置、K线承接、低吸条件。

## 每日应完成的链路

1. 数据更新：行情、成交额、换手率、指数、板块成分。
2. 评分生成：大盘、板块、龙头、个股。
3. 状态识别：短期回调、转弱、退潮、延续。
4. 预警生成：强势板块突然走弱、退潮、高风险变化。
5. K线观察：承接、低吸、弱修复、未见承接。
6. 事件层：政策、公告、业绩、新闻；没有结构化来源时必须标注缺失。
7. 问答/推送：飞书、Telegram、网页报告都只引用已生成证据。

## 工作流体检

运行：

```text
python scripts\run_workflow_status.py
```

输出：

```text
C:\Users\HUAWEI\Documents\股票AI交易助手\reports\workflow\latest_workflow_status.md
```

它会检查：

- 数据是否更新。
- 评分是否生成。
- 退潮预警是否生成。
- K线承接是否生成。
- 事件层是否缺失。
- Telegram/国内大模型是否处于可用状态。

## 当前原则

- 不编造数据。
- 不自动交易。
- 不把分数当绝对买卖信号。
- 没有事件源时，明确说事件面缺失。
- 没有同口径资金数据时，不乱说主力流入流出。

## 手工补事件

当你看到公告、新闻、政策、截图，但系统还没有自动抓到时，可以先手工补一条事件。

示例：

```text
python scripts\add_manual_event.py --title "某公司公告业绩预增" --source "公告" --ts-code 300054.SZ --name 鼎龙股份
```

然后运行：

```text
python scripts\run_event_layer.py
```

系统会把事件按政策、公告、业绩、新闻，以及利好/利空/中性做结构化标记。后续问 Telegram 或看报告时，就不会完全漏掉这类突发信息。
