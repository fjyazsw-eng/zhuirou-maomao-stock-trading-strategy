# 功能路线图

## 1. 路线图原则

项目采用分阶段建设方式，先完成复盘框架，再逐步接入数据、分析和自动化报告。

核心原则：

- 先有标准，再做自动化。
- 先能复盘，再追求效率。
- 先输出证据，再输出结论。
- 不做自动交易，不替代人工决策。

## 2. 第一阶段：文档与框架

目标：建立项目设计、分析框架和复盘标准。

主要任务：

- 创建 README。
- 创建项目总设计文档。
- 创建功能路线图。
- 创建交易决策框架。
- 定义大盘天气分析框架。
- 定义板块周期阶段。
- 定义龙头角色分类。
- 定义证据输出要求。
- 设计未来文件夹结构。

阶段成果：

- 项目有明确用途。
- 项目有清楚边界。
- 每个分析结论都要求证据。
- 后续开发有基础方向。

## 3. 第二阶段：手工复盘模板

目标：先通过人工录入和 AI 辅助生成报告，跑通复盘流程。

计划功能：

- 每日盘后报告模板。
- 每周复盘模板。
- 板块跟踪模板。
- 持仓风险检查模板。
- 六爻周度判断记录模板。
- 重点板块观察清单。

建议新增目录：

```text
reports/
├── daily/
└── weekly/

prompts/
├── 大盘天气/
├── 板块周期/
├── 龙头识别/
└── 复盘报告/
```

## 4. 第三阶段：本地数据结构

目标：为后续行情接入和数据库管理建立数据结构。

计划功能：

- 个股基础信息表。
- 板块基础信息表。
- 行情日线数据表。
- 板块每日状态表。
- 龙头角色记录表。
- 持仓观察记录表。
- 每日复盘记录表。
- 每周复盘记录表。
- 六爻判断对照记录表。

建议新增目录：

```text
data/
├── raw/
├── processed/
└── database/
```

可选数据库：

- SQLite。
- DuckDB。
- 本地 CSV 或 Parquet 文件。

## 5. 第四阶段：行情数据源接入

目标：接入行情数据源，减少手工整理成本。

计划功能：

- 获取指数行情。
- 获取个股行情。
- 获取板块行情。
- 获取成交额数据。
- 获取涨停、跌停、连板数据。
- 获取重点板块成分股。
- 获取核心个股历史走势。

注意：

- 数据源必须标注来源。
- 数据必须保存原始版本。
- 分析报告必须引用数据时间。
- 对缺失或异常数据必须标注。

## 6. 第五阶段：分析模块

目标：形成可复用的分析模块。

计划模块：

- 大盘天气分析模块。
- 板块周期判断模块。
- 龙头识别模块。
- 持仓风险监控模块。
- 重点板块跟踪模块。
- 每日盘后报告模块。
- 每周复盘模块。
- 六爻与现实市场对照模块。

每个模块必须输出：

- 结论。
- 证据。
- 风险。
- 不确定性。
- 下一步观察。

## 7. 第六阶段：报告自动化

目标：自动生成结构化复盘报告。

计划功能：

- 每日盘后报告自动生成。
- 每周复盘自动生成。
- 重点板块报告自动生成。
- 持仓风险提示自动生成。
- 龙头角色变更记录。
- 周期阶段变化记录。

报告格式优先级：

1. Markdown。
2. HTML。
3. PDF。

## 8. 第七阶段：本地 AI 工作流

目标：让本地 AI 能基于数据、模板和历史复盘生成辅助判断。

计划功能：

- 固定提示词模板。
- 证据引用检查。
- 历史复盘检索。
- 个股和板块画像。
- 自定义观察清单。
- 对同一结论进行多角度校验。

## 9. 暂不进入的范围

以下内容暂时不做：

- 自动下单。
- 自动撤单。
- 券商交易接口。
- 高频交易。
- 无人工确认的实盘交易。
- 任何收益承诺。

## 10. 重点板块规划

第一批重点跟踪板块：

- 半导体。
- 通信设备。
- 券商。

后续可扩展：

- 人工智能。
- 算力。
- 消费电子。
- 新能源。
- 军工。
- 医药。
- 机器人。

每个板块都应维护：

- 板块状态。
- 当前周期阶段。
- 龙头角色。
- 催化因素。
- 资金强度。
- 风险信号。
